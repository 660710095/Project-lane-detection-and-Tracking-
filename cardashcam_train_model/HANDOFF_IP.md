## 1. ส่ง mask มาแบบไหน

| หัวข้อ | ข้อกำหนด |
| --- | --- |
| รูปแบบ | PNG ระดับเทา ค่า 0 กับ 255 |
| ชื่อไฟล์ | **ชื่อเดียวกับภาพต้นฉบับ** เปลี่ยนนามสกุล `.jpg` เป็น `.png` |
| ขนาด | **448×800** หรือทวีคูณลงตัว (896×1600) |
| โฟลเดอร์ | ไฟล์ทั้งหมดอยู่ในโฟลเดอร์เดียว ไม่ต้องแยกโฟลเดอร์ย่อย |

**เรื่องขนาดสำคัญกว่าที่คิด** — วัดแล้ว ส่งมาที่ 896×1600 (2 เท่าพอดี) ได้ตัวเลขตรงเป๊ะ
แต่ส่งมาที่ 1080×1920 (ไม่ลงตัว) ทำให้ **IoU เพี้ยน 0.005-0.010** เพราะพิกเซลเลื่อนตอน resize
สคริปต์จะเตือนให้ถ้าขนาดไม่ลงตัว แต่ส่งมาตรงเลยดีกว่า

## 2. วัดผลยังไง

```bash
python3 eval_masks.py --pred-dir /path/to/masks --tag ip_hough
```

ได้ตารางออกมาทางหน้าจอ และไฟล์ `results/ip/ip_hough.csv`

**ไม่ต้องมีโมเดล ไม่ต้องใช้ GPU** — สคริปต์นี้อ่าน PNG อย่างเดียว

คอลัมน์ที่ได้ เหมือนกับที่ฝั่ง DL ใช้ทุกตัว บวก pixel precision/recall

| คอลัมน์ | หมายถึง |
| --- | --- |
| `iou` `f1` | ความทับซ้อนระดับพิกเซล |
| `median_err` | **มุมของเส้นคลาดจากเฉลยกี่องศา** |
| `acc5` | สัดส่วนเส้นที่มุมคลาดไม่เกิน 5° |
| `lane_recall` | เส้นเฉลยที่จับได้ / เส้นเฉลยทั้งหมด |
| `lane_precision` | เส้นที่จับได้ / เส้นที่ทำนายทั้งหมด |
| `px_recall` `px_precision` | **แยก "มองไม่เห็น" ออกจาก "วาดเกิน"** |

## 4. กับดัก 3 ข้อ ที่ต้องรู้ก่อนเริ่ม

### 4.1 เฉลยไทย label แค่เลนที่รถวิ่งอยู่

วัดจากเฉลยจริง: ไทย **2.00 เส้น/ภาพ** · CULane **3.00 เส้น/ภาพ**

ถ้าวิธีของคุณจับ**เส้นจราจรทุกเส้นที่เห็น** (ซึ่งวิธี CV แบบคลาสสิกมักเป็นแบบนั้น)
คุณจะโดนหักคะแนนทั้งที่ไม่ได้ผิด

โมเดล DL โดนแบบนี้อยู่ — ดูตัวเลข zero-shot

| หมวด | px recall | px precision | เฉลย เส้น/ภาพ | ทำนาย เส้น/ภาพ |
| --- | ---: | ---: | ---: | ---: |
| normal | 0.727 | 0.438 | 1.77 | 3.05 |
| curve | 0.221 | 0.514 | 1.82 | 2.12 |
| night | 0.497 | 0.510 | 1.82 | 2.94 |

`normal` — **px recall 0.727 สูงกว่าตอนวัดบน CULane เอง**
แต่ precision เหลือ 0.438 เพราะวาดเลนข้างเคียงที่เฉลยไม่มี
เส้นที่เกินมา**อยู่บนเส้นจราจรจริง** (ดู `results/thai/convention_extra_lanes.png`)

**เพราะงั้น: อ่าน `px_precision` คู่กับ `px_recall` เสมอ อย่าดู IoU ก้อนเดียว**

ทีมยังไม่ได้ตัดสินใจว่าจะเปลี่ยนวิธี label หรือไม่ — คุยกันให้จบก่อนเริ่ม tune
ไม่งั้นจะไล่ลด false positive ที่จริงๆ ไม่ผิด (รายละเอียด `results/thai/REPORT_ANNOTATION.md` หัวข้อ 4)

### 4.2 `curve` กับ `night` มีหมวดละ 17 ภาพ จาก 1-2 clip

ไทย test เป็น `normal` **82%** (157 จาก 191) แถว ALL จึงถูก `normal` ครอบงำ
และ `night` ทั้ง test มาจาก**คลิปเดียว** ตัวเลขสองหมวดนี้แกว่งมาก

**อย่าอ้างผลจากสองหมวดนี้โดยไม่บอกจำนวนภาพ**

### 4.3 IoU กับมุมคลาดจัดอันดับไม่เหมือนกัน

วัดแล้ว — เลื่อนเส้นข้าง 20px ได้ IoU 0.088 กับมุมคลาด **0.00°** ·
หมุน 10° ได้ IoU 0.123 กับมุมคลาด **9.93°**

IoU เท่ากันแต่ความหมายตรงข้าม **ต้องรายงานทั้งสองตัว**
