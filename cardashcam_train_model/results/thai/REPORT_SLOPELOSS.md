# เอาความชันใส่ loss แล้วดีขึ้นไหม

คำถามจากอาจารย์: *"เราทดลองปรับ loss เป็นความชันแล้ว หรือเทรนปกติแต่วัดต่างกัน"*

**เดิมคือแบบหลัง** — ทุกรันในโปรเจกต์ใช้ `BCEWithLogitsLoss + DiceLoss` เหมือนกันหมด
ความชันเป็นแค่ตัววัดและเกณฑ์เลือก epoch รายงานนี้ปิดช่องว่างนั้น

**คำตอบสั้น: λ=0.1 ล้มเหลว · λ=0.3 ไม่สรุป** — แถว ALL ดีขึ้นผ่านเกณฑ์ แต่**ไม่มีหมวดไหนยืนยัน**

---

## 1. ทำไมใส่ตรงๆ ไม่ได้

`slope_metrics.py` ใช้ของที่ไม่มี gradient สามจุด

| บรรทัด | ฟังก์ชัน |
| ---: | --- |
| 56 | `cv2.connectedComponentsWithStats` |
| 74 | `np.linalg.lstsq` |
| 107 | `scipy.optimize.linear_sum_assignment` (Hungarian) |

`slope_metrics.py` เป็น single source of truth และต้องไม่มี torch จึงสร้าง `slope_loss.py` แยก

## 2. วิธีที่ใช้ — จับคู่โดยไม่เอา gradient แล้วคิด loss แบบมี gradient

แบบเดียวกับที่ DETR ทำกับ Hungarian

1. `no_grad` — threshold 0.5 เรียก `slope_metrics_for_pair` ของเดิม ได้คู่เส้น GT↔pred
2. **มี gradient** — centerline แบบนุ่มจาก `prob` ดิบถ่วงด้วย component mask ของเส้นนั้น
   `x̄(y) = Σₓ x·p·m / Σₓ p·m` แล้ว `torch.linalg.lstsq` แล้ว `atan2(1,a)`
3. `loss = BCE + Dice + λ · mean(|Δมุม|) / 10`

**ไม่ได้ก๊อปสูตรมา** — `lane_components()` เรียก `extract_lanes` กับแต่ละ component แยกกัน
ผลจึงตรงกับของเดิมโดยโครงสร้าง

**ด่านตรวจก่อนเอาไปใช้**

| ตรวจ | ผล |
| --- | --- |
| มุมจาก `soft_angle` บน mask ไบนารี เทียบ `extract_lanes` | คลาดมากสุด **0.0000°** (39 เส้น) |
| gradient ไหลถึง logits | ✓ |
| `lane_components` ได้จำนวนเท่า `extract_lanes` | ✓ |

**ราคา** 805 → **1482 ms/step (1.84×)**

**พฤติกรรมที่ดูเหมือนบั๊กแต่ถูกแล้ว:** เลื่อนเฉลยไป 20px แล้ว loss เกือบ 0
การเลื่อนไม่เปลี่ยนมุม ตรงกับข้อสรุปหลักของโปรเจกต์ที่ว่าเลื่อน 20px ได้มุมคลาด 0.00°
loss ตัวนี้ลงโทษ**ทิศทาง**อย่างเดียวตามที่ตั้งใจ

---

## 3. ผล

ทุก arm ใช้ `--rehearse-frac 0.5 --seed 1` เหมือนกัน เปลี่ยนแค่ λ · เทียบที่ checkpoint เกณฑ์ f1

| arm | λ | epoch | ไทย IoU | ไทย F1 | ไทย มุม | ไทย recall | CULane night มุม |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| control (BCE+Dice) | 0 | 15 | 0.470 | 0.640 | 2.01° | 0.856 | 1.16° |
| + slope loss | 0.1 | 15 | 0.470 | 0.640 | 1.99° | 0.862 | 1.18° |
| + slope loss | 0.3 | 16 | 0.468 | 0.638 | 1.87° | 0.865 | 1.16° |

**เทอมทำงานจริงและถูก optimize** — `train_slope_loss` ลดลงตลอดการเทรน และลดแรงกว่าที่ λ สูง

| | ep1 | ep10 | ep20 | ep30 |
| --- | ---: | ---: | ---: | ---: |
| λ=0.1 | 0.3456 | 0.4100 | 0.3590 | 0.3287 |
| λ=0.3 | 0.3441 | 0.3937 | 0.3272 | 0.2985 |

คู่เส้นที่จับได้ต่ำสุด 1,533 คู่/epoch — ไม่เคยเป็น 0

## 4. แถว ALL หลอก — ด่านตรวจที่ต้องเพิ่ม

เกณฑ์ที่ตั้งไว้**ก่อนรัน**คือ มุมดีขึ้น ≥ 0.10° · IoU ไม่ตกเกิน 0.02 · คู่เส้นไม่เป็น 0

λ=0.3 ผ่านทั้งสามข้อ (Δมุม **+0.14°** · ΔIoU −0.002) **แต่พอแยกหมวดแล้วไม่เข้ากัน**

| arm | normal มุม | curve มุม | night มุม | normal recall | curve recall | night recall |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| control (BCE+Dice) λ=0 | 1.72° | 5.94° | 4.87° | 0.896 | 0.645 | 0.710 |
| + slope loss λ=0.1 | 1.68° | 6.27° | 4.62° | 0.903 | 0.645 | 0.710 |
| + slope loss λ=0.3 | 1.74° | 5.99° | 4.92° | 0.903 | 0.645 | 0.742 |

**λ=0.3 ไม่ดีกว่า control สักหมวดเดียว** (1.74 vs 1.72 · 5.99 vs 5.94 · 4.92 vs 4.87)
แต่แถว ALL ดีขึ้น 0.14°

สาเหตุ: แถว ALL เป็น **pooled median ของทุกคู่เส้น** พอ `lane_recall` เพิ่มขึ้น
(normal 0.896 เป็น 0.903 ·
night 0.710 เป็น 0.742)
องค์ประกอบของคู่ที่เข้ามารวมก็เปลี่ยน แถว ALL จึงขยับได้โดยที่ไม่มีหมวดไหนเล็งดีขึ้นจริง

**จึงเพิ่มด่านตรวจ "ต้องมีหมวดที่ดีขึ้น ≥ 2 จาก 3"** เข้าไปใน `make_slopeloss_report.py`
เป็นการทำให้เกณฑ์**เข้มขึ้น** ไม่ใช่ผ่อนให้ผลผ่าน — บันทึกไว้ตามตรงว่าเพิ่มหลังเห็นผล

| arm | Δมุม ALL | ΔIoU | หมวดที่ดีขึ้น | คำตัดสิน |
| --- | ---: | ---: | ---: | --- |
| λ=0.1 | +0.02° ✗ | −0.000 ✓ | 2/3 ✓ | **ล้มเหลว** (ไม่ถึงบาร์ 0.10°) |
| λ=0.3 | +0.14° ✓ | −0.002 ✓ | **0/3** ✗ | **ไม่สรุป** |

## 5. สิ่งที่พอสรุปได้ และสิ่งที่สรุปไม่ได้

**สรุปได้**

- เอาความชันใส่ loss **ทำได้จริง** และเทอมถูก optimize (ค่าลดลงตลอด 30 epoch)
- **ไม่ทำให้ IoU พัง** — ตก 0.002 ซึ่งอยู่ในระดับ noise
- `lane_recall` ขึ้นเล็กน้อยทุกหมวด ซึ่งไม่ได้คาดไว้ (loss นี้ไม่มีเทอมที่เกี่ยวกับ recall ตรงๆ)
- ราคา 1.84× ต่อ step

**สรุปไม่ได้**

- **ไม่มีหลักฐานว่าเล็งตรงขึ้น** — แถว ALL ที่ดีขึ้นอธิบายได้ด้วย recall ที่เปลี่ยน
  และไม่มีหมวดไหนยืนยัน
- คาดไว้ก่อนรันว่า "มุมดีขึ้นเล็กน้อย IoU ตกเล็กน้อย" — **ผิดทั้งสองส่วน**
  IoU ไม่ตก และมุมก็ไม่ได้ดีขึ้นจริงเมื่อดูรายหมวด

## 6. ข้อจำกัด

- **seed เดียวต่อ arm** ช่วงเหวี่ยงระหว่าง seed ที่วัดไว้ในการทดลองก่อนคือ 0.03°
  ส่วนต่างรายหมวดที่เห็น (0.02-0.05°) จึงอยู่ในระดับเดียวกับ noise
- **λ แค่ 2 ค่า** แนวโน้มบอกว่า λ สูงขึ้นกดเทอมได้แรงขึ้น ยังไม่ได้ลอง λ ≥ 1.0
- **gradient ไหลเฉพาะเส้นที่จับคู่ได้แล้ว** loss นี้สอน "เล็งตรงขึ้น" ไม่ได้สอน "หาเส้นเจอ"
  จึงช่วย `curve` ของไทยไม่ได้ ซึ่งวัดแล้วว่าพังที่ pixel recall 0.221
- ไทย test `curve` และ `night` มีหมวดละ **17 ภาพ จาก 1-2 clip** ตัวเลขสองหมวดนี้แกว่งมาก
